# blindbuild v0.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The planner runs in Claude Code and launches a detached, headless, supervised builder; a background `bb wait` wakes the planner; a read-only viewer shows each agent live.

**Architecture:** `bb run` spawns a detached Node supervisor (`cli.mjs supervise <runDir>`) that runs `claude -p --output-format stream-json`, writes the stream to `runs/<id>/stream.jsonl`, then runs the v0.5 evidence checks and writes `summary.json`. `bb wait` watches that run dir and exits with one of five cases. `bb watch` renders the stream plus per-agent status files. Pure parsing lives in `stream.mjs` so the supervisor, waiter and viewer share it.

**Tech Stack:** Node 18+ ESM, no dependencies, `node:test`. Bash/PowerShell launchers. Claude Code ≥ 2.1.197 (tested).

**Spec:** `docs/superpowers/specs/2026-11-21-v0.6-planner-in-code-design.md`

**Where the work happens:** implement and run the suite in the sandbox mirror `/home/claude/blindbuild`; copy changed files to the laptop repo `C:\code\blindbuild` (source of truth, via Desktop Commander) at the end of each task and run the suite there too (real Windows). Commit on the laptop, on branch `release/v0.6` (created in Task 1 from `main`).

**Release authority (Yashar, 2026-11-21):** once the Task 11 release gate passes (confidence ≥ 9.5), push the branch, open a PR, merge it into `main` after CI is green, tag `v0.6.0`, and publish the GitHub release, without asking again. If the gate does not pass, stop and report instead.

## Global Constraints

- Node 18+, zero dependencies; Windows, macOS, Linux.
- Every argument to a spawned process is passed as an array, never joined into a shell string, except the `.cmd` shim case already handled in `builder-run.mjs`.
- All v0.5 protections stay: main untouched, base branch, user-only `accept`/`promote`/`db-apply`/`halt`, locked rules hash, guard fails closed, plan folder off limits, no AI evidence in git.
- Defaults: `stall_minutes` 10, `max_wait_minutes` 30, `max_parallel_devs` 3, `viewer` `"on"`.
- `bb wait` never kills a process. Never two builders at once (run lock).
- Unknown stream event types are ignored, never thrown on.
- Conventional Commits, no AI trailers, in the laptop repo.

## Review Focus

1. **A long-running tool looks like a stall** (a 15-minute test suite emits no stream events). Expected: `wait` reports `running: <command> for 12m`, not a stall, until the tool has run `stall_minutes × 3`. Test in Task 6.
2. **The planner session restarts mid-run** and calls `bb wait` with no run id. Expected: it attaches to the active run (`state/run.json`), or the newest run dir. Test in Task 6.
3. **The last stream line is half-written** when read. Expected: the parser skips it; the next read picks it up. Test in Task 2.
4. **The repo path contains spaces** (`C:\My Projects\app`). Expected: supervisor spawn and viewer launch both work. Tests in Tasks 5 and 7.
5. **`bb run` twice in quick succession.** Expected: the second refuses with "a builder run is already active". Test in Task 5.

### Task 6: `bb wait`

**Files:** Create: `plugins/blindbuild/scripts/lib/wait.mjs`. Modify: `scripts/cli.mjs`. Test: `plugins/blindbuild/test/wait.test.mjs`.

**Interfaces:**
- Consumes: `readEvents`, `summarize` (Task 2); run files (Task 5).
- Produces: `waitFor(cwd, { runId?, stallMinutes, maxWaitMinutes, pollMs = 2000, now = Date.now }) -> Promise<{ case: 'summary'|'crash'|'stall'|'running'|'timeout', runId, text }>`.
  - Run selection: `runId` → that dir; else the `runLock` run; else the newest `runs/*` dir; none → `{ case: 'timeout', text: 'no run found' }`.
  - `summary`: `summary.json` exists → text = outcome, errors, denials, path to `to-planner.md`.
  - `crash`: no summary and the supervisor pid (from `run.json`) is dead.
  - `stall`: no event for `stallMinutes` and nothing in flight, or a tool in flight longer than `stallMinutes × 3`.
  - `running`: at `maxWaitMinutes` with a tool in flight → text `running: <tool text> for <n>m`.
  - `timeout`: at `maxWaitMinutes`, otherwise → text `still running; last activity <agent>: <text> (<n>m ago)`.
  - CLI `wait [runId]` prints `CASE: <case>` on the first line, then the text; always exits 0.
